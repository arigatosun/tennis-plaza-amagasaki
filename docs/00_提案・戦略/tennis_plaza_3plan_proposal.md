## 0. この設計書が答える1つの問い

> 「で、結局いくらで、どこまでやってくれるん？運用うちで回さなあかんのは、どのプランやったらどれだけ減るん？」（近江・想定）

3プランの差は機能の多寡ではなく、**「近江の手間をアリガトサンがどこまで巻き取るか」の濃淡**です。

- **Light** = 仕組みとテンプレは渡す。手を動かすのはテニプラ（内製支援・伴走）。
- **Standard** = 作る作業（記事・投稿・編集）はアリガトサンが代行。撮影素材だけテニプラ。
- **Full** = ネタ仕入れ・撮影ディレクション・スカウト運用まで巻き取る。**近江の手間ほぼゼロ**。

この一点で読んでください。以下すべてその具体化です。

### 3-2. Full前提KPI と Light前提KPI の差（核心）

- **同じなのは「バケツ（受け皿）」**。求人票・LP・LINE・計測の設計品質はどのプランも同一。永吉フレームの「穴を塞ぐ」はLightでも満たす。
- **違うのは「蛇口（流入を回し続ける力）」**。
  - **Light**: 蛇口をひねる手がテニプラ側。投稿・記事・撮影が現場の繁忙で止まると、LP到達650件→応募50件の前提が崩れる。**採用3人の達成可否が社内稼働量に従属する**＝KPI書の安全係数（応募2.5倍）を食い潰しやすい。
  - **Full**: 蛇口を回す手がアリガトサン。リール本数・スカウト送信数・記事本数を**契約で固定**できるため、KPIの先行指標（投稿本数・スカウト送信数・記事公開数）が計画通り積み上がる。**北極星達成の確度が構造的に高い**。
- 結論: **採用を90日で確実に回すなら、流入の蛇口を契約で固定できるStandard以上が整合的**。Lightは「バケツは塞げるが、蛇口は自分で回す」プラン。

## 4. 推奨プランと提案ストーリー

### 4-1. アリガトサン推奨の入り方

> **「立ち上げはStandard（採用が最速で必要な時期だけFull相当の集中投下も選択肢）→ 採用充足・自走の型が固まったらLightへ移行して維持」**

理由:

1. **採用フェーズは"蛇口を回し続ける力"が成否を分ける**（第3章）。現場が繁忙な今、近江に流入運用を残すと北極星（90日採用）の確度が下がる。立ち上げは代行濃度を上げるのが合理。
2. **バケツ整備（設計）は1回で完了する固定費的工程**。ここを初期費用＋初月で集中的にやり切り、2ヶ月目以降は運用に移る（第5章）。
3. **採用が充足し、まやのさんが手離れし、投稿・記事の"型"が社内に蓄積したら、Lightに落として維持コストを下げられる**。テニプラの費用は「立ち上げ高→維持低」の自然な逓減カーブを描ける。

### 4-2. 長期伴走への接続（スポット制作にしない設計）

- **スポット（LP1本作って終わり）にしないために、本提案は最初から「月額運用＋初期設計」の構造**にしている。初期費用＝バケツ整備、月額＝蛇口を回し続ける伴走。
- ロードマップ4段階（①現状整理→②採用導線→③育成導線→④西宮展開）と接続: **Standard/Fullで採用（②）を回し切る→ Fullで育成（③）に着手→ 西宮（④）は集客フェーズの本丸として次の伴走スコープに自然連結**。
- これにより「採用が終わったら契約終了」ではなく「採用→育成→西宮」と**伴走スコープが事業フェーズに沿って続く**。プラン移行（Standard→Light、または→西宮向けFull）という会話を継続接点にする。

### 4-3. MTGでのプラン選択トーク（中田用）

> 「おすすめは"立ち上げStandard、落ち着いたらLight"です。理由は、採用は流入を止めずに回し続けられるかが勝負で、今のまやのさんに運用を残すと確度が下がるから。最初だけ僕らが蛇口を回しきって、型ができたら維持に切り替える。費用も立ち上げ高・維持低のカーブにできます。もし採用を本気で最速・確実にいくならFull、まず小さく試すならLightから、という3択です。」

## 5. 各プランの工数（アリガトサン計画規律）

### 5-1. 順次必須の明示（短縮しない箇所）

- **「ブランド確定 → 運用」は順次必須**。ブランド（コンセプト/カラー/トンマナ）が固まる前に投稿・記事を量産すると、成果物Aの第1章課題（統一感欠如）が再発する。**Claude並列でも、ここは並列化で短縮しない**。
- 並列可能（同日消化前提）: ブランド確定**後**の記事下書き生成・投稿テンプレ展開・リール台本作成・LINE自動応答文面など、独立した制作タスク群。
- 順次必須の連鎖: `ブランド確定 → 求人票/LP/LINE設計（バケツ） → 計測設定 → 流入運用（蛇口）`。これはKPI書の「採用→集客」順序とも整合。

### 5-2. 立ち上げ（初月）vs 定常運用（2ヶ月目以降）

| プラン | 立ち上げ（初月・主に初期費用に対応） | 定常運用（2ヶ月目以降・月額に対応） |
|---|---|---|
| **Light** | ブランド一式＋テンプレ＋LP導線設計＋LINE初期構築＋計測設定＋運用マニュアル。Claude並列で制作を分担、ブランド確定は順次 | 月次MTG＋伴走Q&A＋レポート雛形更新が主。制作はテニプラ自走（アは設計のメンテのみ） |
| **Standard** | Light相当の設計一式＋求人票/スカウト文＋AI半自動スカウト設計＋計測レポート設計 | 記事4本＋投稿12本＋リール編集8本＋スカウト運用＋月次レポート。**ブランド確定後は並列制作で消化** |
| **Full** | Standard相当＋撮影ディレクション設計＋チラシ＋LINEシナリオ＋（育成導線着手） | 記事6本＋コラム2本＋投稿16本＋リール企画撮影編集8本＋スカウト送信オペ＋LINE運用＋チラシ＋週次レビュー。並列フル稼働 |

- **共通**: 初月は「設計→確定」のリードタイムがあるため、流入成果（応募）は初月に出ない前提（KPI書 Phase1＝バケツ完成度100%で合格）。これは近道防止の構造であり、初月に応募が出ないことを"遅れ"と誤認しない。
- **工数オーバー時の3択**（規律）: [A]品質維持＋納期延長（推奨）／[B]スコープ削減（例: SEO・チラシを後送りしIG＋媒体＋LINEに集中）／[C]近道許容（非推奨・犠牲明示: 求人票/計測の簡易版での先行出稿＝歩留まり低下と改善不能リスク）。

## 6. 契約・法務の注意

### 6-1. 職業紹介事業に触れない切り方

- 本提案の役務は一貫して**「採用マーケ支援／採用広報／媒体運用支援／スカウト文・求人票・LP設計」**。**候補者を紹介して成功報酬を取る形（職業紹介事業の領域）には踏み込まない**。
- 課金は**月額（運用代行）＋初期費用（設計）**の固定/定額型。**「採用1人決定でいくら」の成功報酬型にしない**（職業紹介に近づくため）。
- 契約書面でも役務を「制作・運用・コンサルティング」と定義し、紹介行為・あっせんを業務範囲から除外する。

### 6-2. AIスカウトは「半自動」表現で統一

- AIは**候補抽出と文面下書きまで**。**最終判断・送信は人**。資料・契約・口頭すべてで「**半自動（最終送信は人）**」と表現する。
- KPI上も「スカウト送信数」は人の承認を経た送信としてカウント（成果物B 6-3と整合）。

### 6-3. 媒体（doda等）とは競合でなく「上流補完」の立て付け

- doda／リクルート／Indeed＝**蛇口（母集団の入口）**。アリガトサン＝**バケツ（受け皿＝LP/求人票/面談導線）と蛇口の運用支援**。
- テニプラがdoda等と商談中である点を踏まえ、**「媒体を置き換える提案ではなく、媒体の費用対効果を最大化する受け皿と運用を整える提案」**と位置づける。媒体掲載料は**別途実費**（本月額レンジに含まない）。これにより媒体担当との利害衝突を避け、テニプラ社内でも通しやすい。
